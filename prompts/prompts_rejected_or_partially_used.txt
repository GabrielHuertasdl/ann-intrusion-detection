--------------------------------------------------------------------
REJECTED: 4th hidden layer (64→32 additional block)
--------------------------------------------------------------------
Suggestion:
  Claude recommended adding a 4th hidden layer (64→32) to increase
  representational depth for multi-hop feature abstraction.

Reason for rejection:
  - A 4th layer adds training time on CPU and makes the comparison
    between Part A (3 layers) and Part B less clean.
  - Published results (Moustafa & Slay 2016, Faker & Dogru 2019) show
    that 3-layer ANNs are sufficient to distinguish UNSW-NB15 classes.
  - Diminishing returns expected: the bottleneck is class imbalance
    (Worms: 44 samples), not model depth.
  Decision: retained 3 hidden layers in both parts for a fair comparison.

--------------------------------------------------------------------
REJECTED: SMOTE oversampling for minority classes
--------------------------------------------------------------------
Suggestion:
  "Consider using SMOTE (Synthetic Minority Over-sampling Technique)
   on the training set before model training to address the severe
   imbalance (840× ratio between Normal and Worms)."

Reason for rejection:
  - SMOTE adds a significant preprocessing step that would make Part B
    fundamentally different in pipeline (not just model architecture),
    complicating the comparison with Part A.
  - The scope of this coursework is ANN design, not preprocessing
    strategy; adding SMOTE would shift the focus.
  - Accepted as a legitimate future work direction and documented in
    the report's Limitations section.
  Decision: noted in report; not implemented.

--------------------------------------------------------------------
REJECTED: Temperature scaling for softmax calibration
--------------------------------------------------------------------
Suggestion:
  "Post-training temperature scaling can improve softmax calibration,
   making confidence scores more reliable for the alert thresholds."

Reason for rejection:
  - Temperature scaling requires a held-out calibration set, adding
    a third split beyond train/val/test, which complicates the
    experimental design without proportionate benefit for a coursework.
  - The current confidence distribution (mean correct = 0.90) shows
    reasonably high calibration for the alert use case already.
  Decision: noted as future work; not implemented.

--------------------------------------------------------------------
PARTIALLY USED: Class weighting in CrossEntropyLoss
--------------------------------------------------------------------
Suggestion:
  "Add inverse-frequency class weights to the CrossEntropyLoss to
   penalise the model more heavily for misclassifying rare classes."

Reason for partial rejection:
  - Class weighting changes the loss function, which is a training
    strategy decision, not purely an architecture decision.
  - If applied, it should be consistently applied to both Part A and
    Part B to keep the comparison fair, or explicitly noted as an
    additional Part B technique.
  - In this project, the comparison is focused on architecture
    differences (128→64→32 vs 256→128→64 + BN + L2 + graduated
    dropout), so adding class weights would conflate two variables.
  Decision: documented as a recognised limitation; not implemented.
  Future work: applying class weights uniformly to both models would
  be a controlled experiment worth reporting in future iterations.

--------------------------------------------------------------------

--------------------------------------------------------------------
